## 试题一参考答案：项目章程+开发方法+干系人+CCB（第一批次）

> 考试日期：2024-05-25
> 考点：项目章程 + 开发方法选择（预测/迭代/增量/敏捷）+ 干系人管理 + 变更控制（CCB）
> 满分：40分

---

## 问题1参考答案（10分）

项目章程内容缺陷：

1. **缺少可测量的项目目标和相关的成功标准**：章程仅提到"60天内提高报关效率"，未明确具体的成功标准（如效率提高百分比、OCR识别准确率等）。
2. **缺少整体项目风险**：章程未识别项目面临的整体风险（如AI算法不成熟的技术风险、多语种OCR精度不达标等）。
3. **缺少总体里程碑进度计划**：章程未列出关键里程碑时间节点。
4. **缺少主要相关方列表**：章程中有"关键用户名单"但未包含海关技术负责人、关务部门代表等关键干系人，导致验收时才首次参与。
5. **缺少预批准的财务资源/总体预算**：仅有"拟申请的财务资源"，未明确总体预算。
6. **缺少项目发起人或其他批准项目章程的人员的姓名和职权**：签名不等同于明确姓名和职权。

> **评分标准**：每点2分，答出5点即可得满分10分。

## 问题2参考答案（12分）

（1）平台硬件交付：**A. 预测型方法** — 需求明确、方法成熟、一次性交付，适合瀑布式。
（2）数据采集和标注：**A. 预测型方法** — 一次性交付50万张数据，需求和交付物明确。
（3）OCR模型调试：**B. 迭代型方法** — 多次调试，精度不断提高（反复细化改进同一产品）。
（4）OCR算法开发：**D. 敏捷型方法** — 创新度高、无经验、3天更新一次，需快速反馈迭代。
（5）前端界面开发：**B. 迭代型方法** — 多次演示、澄清范围，通过原型迭代确认需求。
（6）平台操作测试：**C. 增量型方法** — 完成一个功能模块就交付一次培训，逐步增量交付。

> **评分标准**：每个模块2分，共12分。

**辨析要点：**
- **迭代型 vs 敏捷型**：迭代型侧重"同一产品反复打磨改进"（如模型精度从60%→80%→95%）；敏捷型侧重"高不确定性+快速交付反馈循环"（如3天一个Sprint）。
- **迭代型 vs 增量型**：迭代型每次交付的是"整体的改进版"；增量型每次交付的是"新增的一个功能模块"。

## 问题3参考答案（12分）

**（1）小张应让干系人参与的项目工作（6分）：**

- 让海关技术负责人参与**项目规划**和**技术方案评审**，确保技术架构合理、计划可行。
- 让关务部门代表参与**需求确认**和**阶段性验收评审**，确保平台功能满足业务需求。
- 在OCR模型调试和前端界面开发过程中，邀请干系人参与**阶段性演示和评审**，及时获取反馈。
- 让相关干系人参与**变更控制**过程，确保需求变更经过充分沟通和审批。
- 在项目执行过程中，定期向干系人**汇报项目进展**，保持信息透明。
- 不能等到验收时才邀请干系人参与，应在整个项目生命周期中**持续参与**。

> 每点1-2分，答出4-5点即可得6分。

**（2）有效执行干系人绩效域的预期目标（6分）：**

- 与干系人建立高效的工作关系。
- 干系人认同项目目标。
- 支持项目的干系人提高了满意度，并从中受益。
- 反对项目的干系人没有对项目产生负面影响。

> 每点1.5分，共6分。这4条是教材原文，尽量一字不差地背下来。

## 问题4参考答案（6分）

（1）**×** — 紧急变更可在事后补审；并非所有变更都必须经CCB审批（如低影响变更可授权PM审批）。
（2）**×** — CCB负责**审批**变更方案，不负责提出方案；提出变更方案是变更申请人或PM的职责。
（3）**√** — CCB通常由主要干系人组成，包括客户/用户代表。
（4）**×** — 批准的变更请求可能导致项目管理计划和项目文件更新。
（5）**√** — CCB是项目的所有者权益代表。
（6）**×** — CCB是**决策机构**，不是作业机构。

> 每小题1分，共6分。

**易错点提醒：**
- 第（1）题容易误选√，关键在于"必须"二字过于绝对。紧急变更可先执行、后补批。
- 第（2）题区分"谁提出"和"谁审批"：PM/申请人提出方案 → CCB审批决策。

## 试题二参考答案：挣值管理EVM计算题（第二批次）

> 考试日期：2024-05-25
> 考点：挣值管理（EVM）+ CV/SV计算 + 绩效评估 + ETC/EAC预测
> 满分：25分

---

### 问题1参考答案（4分）

根据项目数据表，每月实际花费分别为：15、25、30、20、30、35、20（万元）。

可以确定 **第1** 月份的实际花费最低，仅为 **15** 万元。

> 每空2分，共4分。本题为送分题，直接看表即可。

---

### 问题2参考答案（8分）

**已知条件：**
- BAC（完工预算）= 210万元
- 计划工期 = 10个月
- 第7个月底，实际完成了总计划进度的70%

**第7个月底的 PV 计算：**

前7个月每月计划完成量之和 = 5% + 10% + 15% + 15% + 15% + 20% + 10% = 90%

PV = BAC × 90% = 210 × 90% = **189万元**

**第7个月底的 AC 计算：**

前7个月每月实际花费之和 = 15 + 25 + 30 + 20 + 30 + 35 + 20 = **175万元**

**第7个月底的 EV 计算：**

EV = BAC × 实际完成比例 = 210 × 70% = **147万元**

**CV（成本偏差）：**

CV = EV - AC = 147 - 175 = **-28万元**

**SV（进度偏差）：**

SV = EV - PV = 147 - 189 = **-42万元**

> EV、PV、AC 各2分，CV 1分，SV 1分，共8分。注意中间计算过程要写清楚。

---

### 问题3参考答案（8分）

**绩效评估：**

CPI = EV / AC = 147 / 175 = **0.84**（< 1）

SPI = EV / PV = 147 / 189 ≈ **0.78**（< 1）

**结论：** CV = -28万 < 0，SV = -42万 < 0；CPI < 1，SPI < 1。说明项目 **成本超支且进度滞后**，双重偏差，项目绩效不佳。

**改进措施：**

1. **进度方面**：分析进度滞后的原因，采取赶工（加班/加人）或快速跟进（并行活动）等进度压缩技术，加快项目执行速度。
2. **成本方面**：分析成本超支的原因，严格控制后续支出，优化资源配置，减少不必要的开支。
3. 加强项目监控，提高绩效评估的频率，及时发现和纠正偏差。
4. 必要时提交变更请求，调整项目计划、预算或范围。
5. 加强沟通管理，确保团队成员理解项目目标和当前状况，提高工作效率。

> 绩效评估（CPI、SPI计算及结论）4分，改进措施4分（每点1分，答出4点即可）。

---

### 问题4参考答案（5分）

**题意：** 第7个月底找到并纠正了偏差原因，意味着后续工作将按原计划效率执行（即"非典型偏差"）。

**ETC（完工尚需估算）：**

非典型偏差公式：ETC = BAC - EV = 210 - 147 = **63万元**

**EAC（完工估算）：**

EAC = AC + ETC = 175 + 63 = **238万元**

**工期预测：**

已完成70%的工作用了7个月。剩余30%的工作，按原计划效率执行。

原计划效率：10个月完成100%，即每月完成10%。剩余30%需要 30% / 10% = **3个月**。

预计完工时间 = 7 + 3 = **10个月**，与原计划工期相同。

**结论：** 项目完成时间较原计划 **不变**（仍为10个月），但成本将超支238 - 210 = 28万元。

> ETC 2分，EAC 2分，工期判断1分。

**易错点提醒：**
- "找到原因并纠正了偏差"＝非典型偏差，用 ETC = BAC - EV，不用 ETC = (BAC - EV) / CPI。
- 工期预测要注意：纠正偏差后按原计划效率进行，剩余30%对应原计划3个月（第8、9、10月计划完成量加起来正好是 5% + 5% + 0% ... 不对，我们需要看原计划：前7月完成90%，后3月完成10%）。但实际只完成了70%，还差30%。按纠正后的原计划效率（每月10%），需3个月。总工期 = 7 + 3 = 10个月 = 原计划，故"不变"。
- 另一种理解：SPI纠正后为1，剩余工期 = 剩余原计划工期 = 3个月，总工期10个月，不变。
