## 一、信息系统治理概述

本单元属于综合知识科目的"重要"级别，案例分析也可能涉及。核心内容分三块：**IT治理**（框架、体系、任务、方法）、**IT审计**（流程、内容、方法）。考试重点在各治理框架的区分（COBIT/ITIL/ISO标准）和IT审计的流程步骤。

## 二、IT治理

### 2.1 IT治理基础

**IT治理**是指导和控制企业IT使用的体系，目标是确保IT支持并延伸企业战略和目标，同时管理IT相关风险。

IT治理的**核心问题**：IT与业务战略是否一致？IT投资是否产生了预期价值？IT风险是否得到有效管理？

IT治理与IT管理的区别：

| 维度 | IT治理 | IT管理 |
|------|--------|--------|
| **关注层次** | 战略层（董事会/高管） | 运营层（IT部门） |
| **关注问题** | 做正确的事 | 把事情做正确 |
| **时间维度** | 长期 | 短期/日常 |
| **决策类型** | 方向性决策 | 执行性决策 |

### 2.2 IT治理体系

IT治理体系的**五大核心领域**：

| 领域 | 说明 |
|------|------|
| **战略一致** | IT战略与业务战略保持一致 |
| **价值交付** | 确保IT投资产生预期价值 |
| **风险管理** | 识别和管理IT相关风险 |
| **资源管理** | 优化IT资源（人员/技术/信息/基础设施）的使用 |
| **绩效测量** | 跟踪和监控IT战略实施情况 |

> 记忆口诀：**战价风资绩**（战略一致、价值交付、风险管理、资源管理、绩效测量）

### 2.3 IT治理任务

IT治理的主要任务：
- 制定IT战略，确保与业务战略一致
- 建立IT治理架构和决策机制
- 管理IT投资组合，优化资源配置
- 监督IT风险和合规情况
- 评估IT绩效，持续改进

### 2.4 IT治理方法与标准

主要IT治理框架对比：

| 框架/标准 | 全称 | 定位 | 关注点 |
|---------|------|------|--------|
| **COBIT** | 信息和相关技术控制目标 | IT**治理**框架（战略层） | IT与业务目标对齐、控制目标 |
| **ITIL** | IT基础架构库 | IT**服务管理**框架（运营层） | IT服务的规划、交付和支持 |
| **ISO/IEC 38500** | IT治理国际标准 | IT治理**国际标准**（董事会视角） | 六大原则，原则性指导 |
| **ISO/IEC 27001** | 信息安全管理体系 | 信息**安全**管理标准 | 信息安全风险管理 |
| **CMMI** | 能力成熟度模型集成 | 软件过程**改进**框架 | 软件开发过程成熟度 |

> 记忆要点：**COBIT=治理（战略）；ITIL=服务管理（运营）；ISO/IEC 38500=治理国际标准（董事会）**

**ISO/IEC 38500 六大原则**：责任、战略、采购、绩效、一致性、人类行为。

**COBIT 核心思想**：将IT活动组织为域（Domain）和过程（Process），通过控制目标确保IT治理有效。COBIT 5 包含5个域：评估指导监督（EDM）、对齐规划组织（APO）、构建获取实施（BAI）、交付服务支持（DSS）、监控评估评价（MEA）。

## 三、IT审计

### 3.1 IT审计基础

**IT审计**是对组织的信息技术基础设施、应用系统、数据管理和IT治理进行独立评估，以确认IT控制的有效性、数据的完整性和系统的安全性。

IT审计的**目标**：
- 评估IT系统和控制的有效性
- 验证数据的完整性和准确性
- 评估IT风险管理的充分性
- 确保IT合规（法律法规、内部政策）

IT审计与财务审计的关系：IT审计是财务审计的重要组成部分，也可以独立进行。

### 3.2 审计方法与技术

**IT审计的主要方法**：

| 方法 | 说明 |
|------|------|
| **访谈** | 与相关人员交流，了解控制流程 |
| **观察** | 现场观察IT操作和流程 |
| **检查** | 审查文档、记录、报告 |
| **测试** | 对系统和控制进行技术测试 |
| **数据分析** | 使用审计软件分析大量数据 |

**计算机辅助审计技术（CAAT）**：利用审计软件对被审计系统的数据进行分析，提高审计效率和覆盖面。

### 3.3 审计流程

IT审计的标准流程（四个阶段）：

| 阶段 | 主要工作 |
|------|---------|
| **审计准备** | 确定审计范围、目标、方法；制定审计计划；了解被审计对象 |
| **审计实施** | 收集证据；测试控制；执行审计程序 |
| **审计报告** | 汇总审计发现；形成审计意见；出具审计报告 |
| **后续跟踪** | 跟踪审计建议的落实情况；验证整改效果 |

> 记忆口诀：**准实报跟**（准备→实施→报告→跟踪）

### 3.4 审计内容

IT审计的主要内容：

| 审计领域 | 审计重点 |
|---------|---------|
| **IT治理审计** | IT战略一致性、IT决策机制、IT投资管理 |
| **IT基础设施审计** | 网络安全、硬件管理、数据中心运营 |
| **应用系统审计** | 系统开发控制、变更管理、访问控制 |
| **数据管理审计** | 数据完整性、备份恢复、数据安全 |
| **信息安全审计** | 安全策略、访问控制、安全事件管理 |
| **业务连续性审计** | 灾难恢复计划、业务连续性计划（BCP） |

## 四、信息系统治理相关标准

### 4.1 信息安全管理体系（ISMS）

**ISO/IEC 27001**：信息安全管理体系国际标准，基于风险管理方法，通过PDCA循环持续改进信息安全。

**等级保护（等保）**：中国信息安全等级保护制度，共5级，存在两套命名体系：

| 级别 | 体系一（GB 17859-1999） | 体系二（等保2.0实务） |
|------|------------------------|---------------------|
| 第一级 | 用户自主保护级 | 自主保护级 |
| 第二级 | 系统审计保护级 | 指导保护级 |
| 第三级 | 安全标记保护级 | 监督保护级 |
| 第四级 | 结构化保护级 | 强制保护级 |
| 第五级 | 访问验证保护级 | 专控保护级 |

> 体系一口诀：**自审标结访**；体系二口诀：**自指监强专**
> 第三级需公安机关监督检查。考试两套都可能考，务必都记住。

### 4.2 IT服务管理（ITSM）

**ITIL（IT基础架构库）**：IT服务管理最佳实践框架，关注IT服务的全生命周期管理。

ITIL v3 将IT服务管理划分为五个**生命周期阶段**，各核心流程归属如下：

| 生命周期阶段 | 核心流程 | 说明 |
|-------------|---------|------|
| **服务战略** | 战略管理、服务组合管理、财务管理、需求管理、业务关系管理 | 定方向 |
| **服务设计** | **服务级别管理**、**容量管理**、**可用性管理**、IT服务连续性管理、信息安全管理、供应商管理、服务目录管理、设计协调 | 出蓝图 |
| **服务转换** | **变更管理**、**发布管理**、**配置管理**、知识管理、转换规划 | 做上线 |
| **服务运营** | **事件管理**、**问题管理**、请求履行、访问管理 | 保运行 |
| **持续服务改进** | 七步改进法 | 持续优化 |

> 记忆口诀：**战设转运改**（战略→设计→转换→运营→改进）
> 高频考点：事件管理/问题管理=服务运营；服务级别管理/容量管理/可用性管理=服务设计；变更管理/配置管理=服务转换
> **事件管理=救火（快速恢复）；问题管理=防火（找根因）**，两者目标不同。

### 4.3 软件过程改进（CMMI）

**CMMI（能力成熟度模型集成）**：评估和改进软件开发过程的框架。

CMMI五个成熟度级别：

| 级别 | 名称 | 特征 |
|------|------|------|
| **1级** | 初始级 | 过程混乱，依赖个人能力 |
| **2级** | 已管理级 | 项目级过程管理，可重复 |
| **3级** | 已定义级 | 组织级标准过程，文档化 |
| **4级** | 量化管理级 | 过程量化控制，数据驱动 |
| **5级** | 优化级 | 持续过程改进，最高级 |

> 记忆口诀：**初管定量优**（初始→已管理→已定义→量化管理→优化）

## 五、高频考点汇总

1. **COBIT vs ITIL**：COBIT是IT**治理**框架（战略层），ITIL是IT**服务管理**框架（运营层），两者定位不同，高频混淆点。
2. **IT治理五大领域**：战略一致、价值交付、风险管理、资源管理、绩效测量——口诀"战价风资绩"。
3. **事件管理 vs 问题管理**：事件管理救火（快速恢复服务），问题管理防火（找根因永久解决）。
4. **IT审计四阶段**：准备→实施→报告→跟踪——口诀"准实报跟"。
5. **等保五级**：第一级最低，第五级最高，第三级需公安机关监督。存在两套命名体系（GB 17859: 自审标结访；等保2.0: 自指监强专）。
6. **CMMI五级**：初始→已管理→已定义→量化管理→优化，口诀"初管定量优"。
7. **ISO/IEC 38500**：IT治理国际标准，董事会视角，六大原则（责任/战略/采购/绩效/一致性/人类行为）。

## 六、易错点

- ❌ COBIT 是 IT 服务管理框架 → ✅ COBIT 是 IT **治理**框架，ITIL 才是服务管理框架
- ❌ IT 治理和 IT 管理是同一回事 → ✅ IT 治理关注战略层（做正确的事），IT 管理关注运营层（把事做正确）
- ❌ 事件管理的目标是找到根本原因 → ✅ 事件管理目标是**快速恢复服务**，找根因是问题管理的目标
- ❌ 等保第五级是最低级 → ✅ 第**一**级最低，第**五**级最高
- ❌ 等保只有一套名称 → ✅ 存在两套命名体系（GB 17859 和 等保2.0），考试两套都可能考
- ❌ ITIL 各流程不分阶段 → ✅ ITIL v3 明确分五个生命周期阶段（战设转运改），事件/问题管理=运营，服务级别/容量/可用性=设计
- ❌ CMMI 第三级是最高级 → ✅ CMMI 最高级是第**五**级（优化级）
- ❌ ISO/IEC 27001 是 IT 治理标准 → ✅ ISO/IEC 27001 是**信息安全管理**标准，ISO/IEC 38500 才是 IT 治理标准

**第 1 题** 以下关于 COBIT 和 ITIL 的说法，正确的是？

A. COBIT 是 IT 服务管理框架，关注 IT 服务的规划、交付和支持
B. ITIL 是 IT 治理框架，帮助董事会确保 IT 与业务战略一致
C. COBIT 是 IT 治理框架，关注 IT 与业务目标对齐；ITIL 是 IT 服务管理框架，关注服务交付 ✅
D. COBIT 和 ITIL 都是 IT 治理框架，只是适用规模不同

**解析**：COBIT=IT治理框架（战略层），ITIL=IT服务管理框架（运营层）。A/B 把两者互换，D 说"都是治理框架"错误。

**第 2 题** IT 治理的五大核心领域中，确保 IT 投资产生预期回报属于哪个领域？

A. 战略一致
B. 价值交付 ✅
C. 风险管理
D. 绩效测量

**解析**：价值交付=确保IT投资产生预期价值。战略一致是方向对齐，绩效测量是跟踪监控，两者都不是"产生回报"的概念。

**第 3 题** 某公司生产系统突然宕机，IT 运维团队立即启动应急响应，在 30 分钟内恢复了系统服务。事后，团队又花了两周时间深入分析，找到了导致宕机的根本原因并彻底修复。以上两个活动分别对应 ITIL 的哪两个流程？

A. 变更管理 → 问题管理
B. 事件管理 → 问题管理 ✅
C. 问题管理 → 变更管理
D. 事件管理 → 配置管理

**解析**：30分钟内恢复服务=事件管理（救火）；事后找根因彻底修复=问题管理（防火）。两个流程目标截然不同。

**第 4 题** 以下关于信息安全等级保护的说法，正确的是？

A. 等保共分为三级，第三级安全要求最高
B. 等保共分为五级，第五级安全要求最高，第二级需要公安机关监督检查
C. 等保共分为五级，第一级最低，第三级需要公安机关监督检查 ✅
D. 等保共分为五级，所有级别都需要公安机关定期监督检查

**第 5 题** 某软件公司已经建立了组织级标准软件开发过程，所有项目都按照统一的标准流程执行，并有完整的文档记录。根据 CMMI 成熟度模型，该公司处于哪个级别？

A. 第二级（已管理级）
B. 第三级（已定义级） ✅
C. 第四级（量化管理级）
D. 第五级（优化级）

**解析**："组织级标准流程+统一执行+完整文档"是第三级（已定义级）的典型特征。第二级只是项目级可重复，第四级需要量化数据驱动。

**第 6 题** ISO/IEC 38500 与 COBIT 同属 IT 治理领域，以下关于两者区别的说法，正确的是？

A. ISO/IEC 38500 是具体实施框架，提供详细的控制目标；COBIT 是原则性标准
B. ISO/IEC 38500 是面向董事会的原则性治理标准；COBIT 是提供具体实施指导的治理框架 ✅
C. 两者完全相同，ISO/IEC 38500 是 COBIT 的国际化版本
D. ISO/IEC 38500 关注 IT 服务管理，COBIT 关注 IT 治理

**解析**：ISO/IEC 38500 是面向董事会的原则性标准（六大原则，指导性）；COBIT 是提供具体实施指导的治理框架（有详细控制目标）。A 把两者说反了。
