## 一、IT 治理

### 什么是 IT 治理

**IT 治理**：确保 IT 与组织战略目标一致，并对 IT 的使用进行有效管控的体系。

IT 治理的核心目标：
- **战略一致性**：IT 战略与业务战略保持一致
- **价值交付**：确保 IT 投资产生预期价值
- **风险管理**：识别和管控 IT 相关风险
- **资源管理**：优化 IT 资源的使用
- **绩效管理**：跟踪和评估 IT 绩效

### IT 治理主要框架（高频考点）

| 框架 | 全称 | 关注点 |
|------|------|------|
| **COBIT** | 信息和相关技术控制目标 | IT 治理和管理的综合框架，最权威 |
| **ITIL** | IT 基础架构库 | IT 服务管理最佳实践 |
| **ISO/IEC 38500** | IT 治理国际标准 | 董事会层面的 IT 治理指南 |
| **CMMI** | 能力成熟度模型集成 | 软件过程改进和能力评估 |

> 记忆要点：COBIT 是 IT **治理**框架，ITIL 是 IT **服务管理**框架，两者经常一起考

## 二、信息系统管理

### 信息系统生命周期

信息系统从立项到退役经历完整的生命周期：

```
立项 → 开发 → 运维 → 消亡
```

各阶段核心任务：

| 阶段 | 核心任务 | 关键输出 |
|------|------|------|
| **立项阶段** | 可行性研究、需求分析 | 可行性研究报告、项目建议书 |
| **开发阶段** | 系统设计、编码、测试 | 系统软件、测试报告 |
| **运维阶段** | 日常运行、维护优化 | 运维记录、变更记录 |
| **消亡阶段** | 系统迁移、数据归档 | 迁移方案、归档数据 |

### 软件开发模型（高频考点）

| 模型 | 特点 | 适用场景 |
|------|------|------|
| **瀑布模型** | 顺序执行，阶段不可回退 | 需求明确、变化少的项目 |
| **原型模型** | 先做原型验证需求 | 需求不明确的项目 |
| **螺旋模型** | 迭代 + 风险驱动 | 大型、高风险项目 |
| **敏捷模型** | 迭代交付、拥抱变化 | 需求频繁变化的项目 |
| **V 模型** | 开发与测试对应 | 强调测试的项目 |

> 高项考试中，**瀑布模型**和**敏捷**是最常考的两个，要能说出各自的优缺点

## 三、IT 服务管理（ITIL）

ITIL 将 IT 服务管理分为五个核心阶段：

| 阶段 | 核心内容 |
|------|------|
| **服务战略** | 确定提供哪些服务，如何创造价值 |
| **服务设计** | 设计新服务或改进现有服务 |
| **服务转换** | 将设计好的服务部署到生产环境 |
| **服务运营** | 日常运行和支持，处理事件和问题 |
| **持续服务改进** | 持续优化服务质量和效率 |

### 服务运营中的重要概念（高频）

- **事件（Incident）**：导致服务中断或降级的非计划事件，目标是**尽快恢复服务**
- **问题（Problem）**：事件的根本原因，目标是**找到根因并永久解决**
- **变更（Change）**：对 IT 基础设施的有计划修改，需要走变更管理流程
- **服务级别协议（SLA）**：服务提供方与客户之间关于服务质量的协议

> 易混淆：事件管理 ≠ 问题管理。事件是"救火"（快速恢复），问题是"防火"（根因分析）

## 四、信息系统安全管理

### 安全管理体系

**信息安全管理体系（ISMS）**：ISO/IEC 27001 是最权威的信息安全管理标准。

安全管理的 PDCA 循环：
- **Plan（规划）**：建立安全策略和目标
- **Do（执行）**：实施安全控制措施
- **Check（检查）**：监控和审查安全效果
- **Act（改进）**：持续改进安全体系

### 访问控制模型（高频）

| 模型 | 说明 | 特点 |
|------|------|------|
| **DAC**（自主访问控制） | 资源所有者决定访问权限 | 灵活，但安全性较低 |
| **MAC**（强制访问控制） | 系统强制执行安全策略 | 安全性高，用于军事/政府 |
| **RBAC**（基于角色的访问控制） | 按角色分配权限 | 最常用，易于管理 |

> 企业信息系统中 **RBAC** 最常见，考试中出现"按岗位/角色分配权限"就是 RBAC

### 等级保护（等保）

我国信息安全等级保护分为 5 个级别：

| 级别 | 适用范围 |
|------|------|
| 第一级（自主保护级） | 一般信息系统 |
| 第二级（指导保护级） | 一般重要信息系统 |
| 第三级（监督保护级） | 重要信息系统（需公安机关监督） |
| 第四级（强制保护级） | 涉及国家安全的重要系统 |
| 第五级（专控保护级） | 极端重要系统（最高级） |

> 大多数企业信息系统要求达到**第二级或第三级**

## 五、数据管理

### 数据治理

**数据治理**：对数据资产进行管理的策略、流程和标准体系。

核心内容：数据质量管理、数据安全管理、数据标准管理、元数据管理、主数据管理。

### 数据库基础（高频考点）

**三范式**：
- **第一范式（1NF）**：每列不可再分（原子性）
- **第二范式（2NF）**：非主键列完全依赖主键（消除部分依赖）
- **第三范式（3NF）**：非主键列直接依赖主键（消除传递依赖）

**事务的 ACID 特性**：
- **Atomicity（原子性）**：事务要么全部成功，要么全部回滚
- **Consistency（一致性）**：事务前后数据保持一致状态
- **Isolation（隔离性）**：并发事务互不干扰
- **Durability（持久性）**：提交后数据永久保存

## 六、高频考点汇总

1. **COBIT** 是 IT 治理框架，**ITIL** 是 IT 服务管理框架
2. 软件开发模型：瀑布（需求明确）、螺旋（高风险）、敏捷（需求多变）
3. 事件管理（快速恢复）vs 问题管理（根因分析）
4. 访问控制：企业最常用 **RBAC**（基于角色）
5. 等保第三级需要公安机关监督，是大多数重要系统的要求
6. 数据库三范式和事务 ACID 特性

---

## 七、易错点

- ❌ ITIL 是 IT 治理框架 → ✅ ITIL 是 **IT 服务管理**框架，COBIT 才是治理框架
- ❌ 事件管理的目标是找到根本原因 → ✅ 事件管理目标是**快速恢复服务**，找根因是问题管理
- ❌ 瀑布模型适合需求不明确的项目 → ✅ 瀑布模型适合**需求明确**的项目，需求不明确用原型模型
- ❌ 等保第五级是最低级别 → ✅ 第一级最低，**第五级最高**
- ❌ RBAC 是军事系统常用的访问控制 → ✅ 军事系统用 MAC，企业系统用 **RBAC**

**第 1 题** 以下关于 COBIT 和 ITIL 的说法，正确的是？

- A. COBIT 是 IT 服务管理框架，ITIL 是 IT 治理框架
- B. COBIT 关注 IT 治理，ITIL 关注 IT 服务管理
- C. COBIT 和 ITIL 都是 IT 治理框架，功能相同
- D. ITIL 是由 ISO 组织发布的国际标准

**答案：B** | 我的答案：B ✅

**解析**：COBIT 管治理（战略决策层），ITIL 管服务（运营执行层），这是最常考的区分点。

---

**第 2 题** 某系统连续三天在高峰期出现响应超时，运维团队每次都通过重启服务临时恢复，但问题仍然反复出现。此时运维团队应该启动哪个管理流程？

- A. 事件管理，尽快恢复服务
- B. 变更管理，申请扩容服务器
- C. 问题管理，分析根本原因
- D. 服务级别管理，修订 SLA 指标

**答案：C** | 我的答案：C ✅

**解析**：关键词是"反复出现"——每次重启只是临时恢复（事件管理），根因没解决，所以要启动问题管理。如果只是第一次出现，启动事件管理就够了。

---

**第 3 题** 某企业为不同岗位的员工分配不同的系统权限，销售人员只能访问 CRM 模块，财务人员只能访问财务模块。这种访问控制方式属于？

- A. DAC（自主访问控制）
- B. MAC（强制访问控制）
- C. RBAC（基于角色的访问控制）
- D. ACL（访问控制列表）

**答案：C** | 我的答案：C ✅

**解析**："按岗位/角色分配权限"就是 RBAC 的典型描述，企业信息系统中最常见。

---

**第 4 题** 关于软件开发模型，下列说法正确的是？

- A. 瀑布模型适合需求不明确、变化频繁的项目
- B. 螺旋模型以风险驱动为核心，适合大型高风险项目
- C. 敏捷模型要求在项目开始前完整定义所有需求
- D. 原型模型适合需求非常明确的项目

**答案：B** | 我的答案：B ✅

**解析**：螺旋模型 = 迭代 + 风险驱动，每次迭代都要做风险评估，适合大型复杂项目。A 错在瀑布适合需求明确；C 错在敏捷恰恰不要求提前定义所有需求；D 错在原型适合需求不明确的场景。

---

**第 5 题** 数据库事务的 ACID 特性中，"多个事务并发执行时互不干扰"描述的是哪个特性？

- A. 原子性（Atomicity）
- B. 一致性（Consistency）
- C. 隔离性（Isolation）
- D. 持久性（Durability）

**答案：C** | 我的答案：C ✅

**解析**：隔离性（Isolation）就是并发事务互不干扰。原子性是"全成功或全回滚"，一致性是"前后状态合法"，持久性是"提交后永久保存"。
