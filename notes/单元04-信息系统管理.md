## 二、信息系统运行管理

### 2.1 信息系统运维概述

**信息系统运维（IT运维）**是指对已投入运行的信息系统进行日常管理、监控、维护和优化，确保系统持续稳定运行，满足业务需求。

运维管理的**核心目标**：保障系统可用性、可靠性、安全性，降低运营成本，提升服务质量。

### 2.2 运维服务的分类

信息系统运维服务按内容分为四类：

| 运维类型 | 说明 | 典型工作 |
|---------|------|---------|
| **纠错性维护** | 修复已发现的错误/故障 | 修复Bug、排查故障 |
| **适应性维护** | 适应环境变化（硬件/OS/法规变化） | 系统迁移、合规改造 |
| **完善性维护** | 增加新功能或改善性能 | 功能扩展、性能优化 |
| **预防性维护** | 主动预防潜在问题 | 定期巡检、容量规划 |

> 记忆口诀：**纠适完预**（纠错→适应→完善→预防）
> 
> 考试陷阱：**完善性维护**是四类中**工作量最大**的，占运维总工作量的 50%～60%。

### 2.3 运维管理的主要内容

| 管理领域 | 主要工作 |
|---------|---------|
| **配置管理** | 记录和管理IT资产（硬件/软件/文档）的配置信息 |
| **变更管理** | 控制对系统的变更，减少变更带来的风险 |
| **事件管理** | 快速响应和恢复服务中断（救火） |
| **问题管理** | 找到事件根因，永久解决（防火） |
| **发布管理** | 安全地将新版本部署到生产环境 |
| **容量管理** | 确保IT资源满足当前和未来的业务需求 |
| **可用性管理** | 确保IT服务在约定时间内可用 |
| **服务级别管理** | 定义、监控和报告SLA（服务级别协议） |

### 2.4 信息系统评价

信息系统评价是对系统运行效果的综合评估，分为三个维度：

| 评价维度 | 说明 |
|---------|------|
| **技术评价** | 系统性能、可靠性、安全性、可维护性 |
| **经济评价** | 投资回报率（ROI）、总拥有成本（TCO）、成本效益分析 |
| **社会评价** | 对组织业务、用户满意度、社会效益的影响 |

**系统可用性**计算公式：

$$可用性 = \frac{MTBF}{MTBF + MTTR} \times 100\%$$

- **MTBF**（Mean Time Between Failures）：平均故障间隔时间，越大越好
- **MTTR**（Mean Time To Repair）：平均修复时间，越小越好

> 记忆要点：可用性 = MTBF / (MTBF + MTTR)，分子是"好的时间"，分母是"总时间"。

## 三、信息系统安全管理

### 3.1 信息安全管理体系

信息安全管理的**三个层次**：

| 层次 | 内容 |
|------|------|
| **技术层次** | 防火墙、加密、入侵检测、访问控制等技术手段 |
| **管理层次** | 安全策略、安全制度、安全培训、安全审计 |
| **法律层次** | 信息安全相关法律法规、标准规范的遵从 |

> 记忆要点：**技术是手段，管理是核心，法律是保障**。三者缺一不可，且管理层次最重要。

### 3.2 信息安全策略

**信息安全策略**是组织对信息安全的总体方针和原则，是所有安全工作的指导文件。

安全策略的**三个基本原则**：

| 原则 | 说明 |
|------|------|
| **最小权限原则** | 用户只拥有完成工作所需的最小权限 |
| **纵深防御原则** | 多层安全控制，单一防线失效不导致全面崩溃 |
| **职责分离原则** | 关键操作由多人分工完成，防止单人舞弊 |

### 3.3 信息安全控制

信息安全控制分为三类：

| 控制类型 | 说明 | 示例 |
|---------|------|------|
| **预防性控制** | 阻止安全事件发生 | 访问控制、加密、防火墙 |
| **检测性控制** | 发现已发生的安全事件 | 入侵检测、日志审计、安全监控 |
| **纠正性控制** | 修复安全事件造成的损害 | 备份恢复、应急响应、灾难恢复 |

> 记忆口诀：**预检纠**（预防→检测→纠正），三类控制形成完整的安全防护闭环。

### 3.4 信息系统安全等级保护

**等级保护（等保）**是中国信息安全的基本制度，共5级：

| 级别 | 名称 | 监管方式 |
|------|------|---------|
| **第一级** | 自主保护级 | 自主保护，无需备案 |
| **第二级** | 指导保护级 | 自主保护，公安机关指导 |
| **第三级** | 监督保护级 | 公安机关**监督检查** |
| **第四级** | 强制保护级 | 公安机关**强制监督** |
| **第五级** | 专控保护级 | 国家指定专门部门监管 |

> 记忆要点：第三级是分水岭，从第三级开始需要公安机关监督检查。

## 四、信息系统开发管理

### 4.1 信息系统生命周期

信息系统的**生命周期**分为五个阶段：

| 阶段 | 主要工作 |
|------|---------|
| **系统规划** | 确定系统目标、可行性分析、制定规划 |
| **系统分析** | 需求分析、业务流程分析、逻辑模型设计 |
| **系统设计** | 总体设计（架构）、详细设计（模块/数据库） |
| **系统实施** | 编码、测试、部署、用户培训 |
| **系统运维** | 日常运行、维护、评价、更新 |

> 记忆口诀：**规分设实运**（规划→分析→设计→实施→运维）

### 4.2 信息系统开发方法

主要开发方法对比：

| 方法 | 特点 | 适用场景 |
|------|------|---------|
| **结构化方法（瀑布模型）** | 顺序执行，阶段清晰，文档完整 | 需求明确、规模较大的系统 |
| **原型法** | 快速构建原型，用户反馈迭代 | 需求不明确，用户参与度高 |
| **面向对象方法** | 以对象为核心，复用性强 | 复杂系统，需要高复用性 |
| **敏捷方法** | 迭代开发，快速响应变化 | 需求变化频繁，小团队 |
| **构件组装方法** | 基于已有构件快速组装 | 有成熟构件库，快速交付 |

> 记忆要点：**原型法**最适合需求不明确的场景；**结构化方法**文档最完整但灵活性最差；**敏捷方法**响应变化最快。

### 4.3 软件测试

软件测试的**四个层次**（从小到大）：

| 测试层次 | 测试对象 | 执行者 |
|---------|---------|-------|
| **单元测试** | 单个模块/函数 | 开发人员 |
| **集成测试** | 模块间接口和交互 | 开发/测试人员 |
| **系统测试** | 整个系统功能和性能 | 测试人员 |
| **验收测试** | 是否满足用户需求 | 用户/客户 |

测试方法：

| 方法 | 说明 |
|------|------|
| **黑盒测试** | 只关注输入输出，不看内部代码（功能测试） |
| **白盒测试** | 关注内部逻辑和代码路径（结构测试） |
| **灰盒测试** | 介于黑盒和白盒之间 |

> 记忆要点：**黑盒=功能测试**（用户视角）；**白盒=结构测试**（开发视角）。验收测试由**用户**执行，不是测试人员。

### 4.4 软件质量模型

**ISO/IEC 25010（SQuaRE）**软件质量模型，定义了软件质量的八大特性：

| 质量特性 | 说明 |
|---------|------|
| **功能适合性** | 功能满足需求的程度 |
| **性能效率** | 在特定条件下的资源使用效率 |
| **兼容性** | 与其他系统共存和交互的能力 |
| **易用性** | 用户使用的方便程度 |
| **可靠性** | 在规定条件下执行功能的能力 |
| **信息安全性** | 保护信息和数据的能力 |
| **可维护性** | 被修改的容易程度 |
| **可移植性** | 从一个环境迁移到另一个环境的能力 |

## 五、信息系统项目管理

### 5.1 信息系统项目的特点

信息系统项目与一般工程项目相比，具有以下特点：

- **需求不确定性高**：用户需求难以在初期完全明确
- **技术复杂性高**：涉及多种技术，集成难度大
- **无形性**：软件产品无形，质量难以直观评估
- **变更频繁**：需求和技术环境变化快
- **人员依赖性强**：高度依赖开发人员的技能和经验

### 5.2 信息系统项目管理的关键成功因素

| 关键因素 | 说明 |
|---------|------|
| **高层支持** | 项目发起人的支持是项目成功的首要因素 |
| **用户参与** | 用户全程参与，确保需求准确 |
| **明确需求** | 需求清晰、稳定，变更受控 |
| **合理规划** | 进度、成本、资源计划合理可行 |
| **有效沟通** | 团队内部和与干系人的沟通顺畅 |

## 六、高频考点汇总

1. **运维四类型**：纠错性、适应性、完善性（工作量最大）、预防性——口诀"纠适完预"。
2. **可用性公式**：可用性 = MTBF / (MTBF + MTTR)，MTBF越大越好，MTTR越小越好。
3. **安全三层次**：技术层次、管理层次（最重要）、法律层次。
4. **安全控制三类**：预防性（阻止）、检测性（发现）、纠正性（修复）——口诀"预检纠"。
5. **等保第三级**：从第三级开始需公安机关监督检查，是分水岭。
6. **系统生命周期五阶段**：规划→分析→设计→实施→运维——口诀"规分设实运"。
7. **开发方法选择**：需求不明确→原型法；需求明确规模大→结构化；变化频繁→敏捷。
8. **验收测试**：由**用户/客户**执行，不是测试人员。

## 七、易错点

- ❌ 完善性维护是最少的维护类型 → ✅ 完善性维护工作量**最大**，占50%～60%
- ❌ 可用性 = MTTR / (MTBF + MTTR) → ✅ 可用性 = **MTBF** / (MTBF + MTTR)，分子是"好的时间"
- ❌ 信息安全最重要的是技术层次 → ✅ **管理层次**最重要，技术是手段，管理是核心
- ❌ 验收测试由测试人员执行 → ✅ 验收测试由**用户/客户**执行
- ❌ 原型法适合需求明确的大型系统 → ✅ 原型法适合**需求不明确**的场景，结构化方法才适合需求明确的大型系统
- ❌ 等保第二级需要公安机关监督检查 → ✅ 从**第三级**开始才需要公安机关监督检查

**第 1 题** 以下关于信息系统运维四种类型的说法，正确的是？

A. 纠错性维护是工作量最大的维护类型，占运维总工作量的 50%～60%
B. 适应性维护是指为适应硬件、操作系统或法规变化而进行的维护 ✅
C. 预防性维护是指增加新功能或改善系统性能的维护活动
D. 完善性维护是指修复已发现的系统错误和故障

**解析**：适应性维护=适应环境变化（硬件/OS/法规），B正确。A错：工作量最大的是**完善性维护**（50%～60%）。C错：增加新功能是完善性维护。D错：修复错误是纠错性维护。

**第 2 题** 某信息系统在过去一年中，累计正常运行时间为 8400 小时，发生故障 10 次，每次平均修复时间为 6 小时。该系统的可用性最接近？

A. 95.0%
B. 96.6%
C. 98.6% ✅
D. 93.3%

**解析**：MTBF = 8400 / 10 = 840小时；MTTR = 6小时。可用性 = MTBF / (MTBF + MTTR) = 840 / (840 + 6) = 840 / 846 ≈ 99.3%，最接近C（98.6%）。

**第 3 题** 某企业安全总监认为"技术手段是信息安全的核心，只要防火墙和加密做好了，安全就有保障"。以下对这一观点的评价，正确的是？

A. 该观点正确，技术层次是信息安全最重要的层次
B. 该观点片面，信息安全需要技术、管理、法律三个层次共同保障，管理层次最重要 ✅
C. 该观点基本正确，技术和管理同等重要，法律层次可以忽略
D. 该观点正确，技术手段能解决所有信息安全问题

**解析**：信息安全三层次：技术（手段）、管理（核心，最重要）、法律（保障）。只靠技术是片面的，B正确。

**第 4 题** 以下关于软件测试层次的说法，正确的是？

A. 集成测试由用户执行，目的是验证系统是否满足业务需求
B. 单元测试关注模块间的接口和交互，由测试人员执行
C. 验收测试由用户或客户执行，目的是确认系统是否满足用户需求 ✅
D. 系统测试是测试的最后阶段，测试完成后直接上线

**解析**：验收测试由**用户/客户**执行，C正确。A错：集成测试由开发/测试人员执行。B错：单元测试关注单个模块，由开发人员执行。D错：系统测试后还有验收测试。

**第 5 题** 某项目需求模糊，用户愿意积极参与并及时反馈。最适合采用的开发方法是？

A. 结构化方法（瀑布模型），因为文档完整，过程清晰
B. 原型法，因为适合需求不明确、用户参与度高的场景 ✅
C. 构件组装方法，因为可以快速复用已有构件
D. 面向对象方法，因为复用性强，适合复杂系统

**解析**：需求不明确 + 用户积极参与 = 原型法的典型适用场景。结构化方法需要需求明确，B正确。

**第 6 题** 以下关于信息安全控制类型的说法，正确的是？

A. 防火墙属于检测性控制，因为它能检测到入侵行为
B. 入侵检测系统（IDS）属于预防性控制，因为它能阻止攻击发生
C. 数据备份与恢复属于纠正性控制，用于修复安全事件造成的损害 ✅
D. 访问控制属于纠正性控制，因为它能纠正非法访问行为

**解析**：数据备份与恢复=纠正性控制（修复损害），C正确。A错：防火墙是**预防性**控制。B错：IDS是**检测性**控制（发现入侵，不能阻止）。D错：访问控制是**预防性**控制。
