## 一、合同法（高频考点）

### 1.1 合同的成立要件

合同成立需要满足：
1. **要约**：一方向另一方提出订立合同的意思表示（具体、确定）
2. **承诺**：另一方对要约的完全同意（不得附加条件，否则视为新要约）

> 关键：承诺必须是**完全同意**，有任何修改都是"反要约"，不构成合同成立

### 1.2 合同的主要条款

合同通常包含：当事人信息、标的、数量、质量、价款、履行期限、履行地点、违约责任、争议解决方式。

### 1.3 合同的效力

| 状态 | 说明 |
|------|------|
| **有效合同** | 双方意思真实、内容合法、主体适格 |
| **无效合同** | 违反法律强制性规定、损害社会公共利益 |
| **可撤销合同** | 存在欺诈、胁迫、重大误解等情形，受损方可申请撤销 |
| **效力待定合同** | 限制民事行为能力人签订，需法定代理人追认 |

### 1.4 违约责任

- **违约金**：合同约定的违约赔偿金额
- **损害赔偿**：实际损失的赔偿（可与违约金并用，但不能超过实际损失）
- **继续履行**：要求违约方继续履行合同义务

## 二、招投标法（高频考点）

### 2.1 招标方式

| 方式 | 说明 | 适用场景 |
|------|------|------|
| **公开招标** | 向社会公开发布招标公告，任何符合条件的供应商均可投标 | 大型项目，金额超过法定限额 |
| **邀请招标** | 向特定的3家以上供应商发出投标邀请书 | 技术复杂、供应商有限的项目 |

> 必须公开招标的情形：国有资金占控股或主导地位的项目，且金额超过规定限额

### 2.2 招标流程

```
发布招标公告 → 资格预审 → 发售招标文件 → 投标 → 开标 → 评标 → 定标 → 签订合同
```

**关键时间节点**：
- 招标文件发出到投标截止：不少于**20天**
- 评标委员会人数：**5人以上单数**，技术/经济专家不少于2/3
- 中标通知书发出后：**30天内**签订合同

### 2.3 评标方法

| 方法 | 说明 | 适用场景 |
|------|------|------|
| **综合评分法** | 对价格、技术、服务等多维度打分，综合最高者中标 | 技术复杂项目 |
| **最低价法（经评审的最低投标价法）** | 满足技术要求前提下，价格最低者中标 | 标准化采购 |

### 2.4 禁止行为

- 禁止**串通投标**（投标人之间协商报价）
- 禁止**低于成本价**投标
- 禁止**转让中标项目**（分包需在合同中约定）
- 中标后**不得拒绝签订合同**

## 三、著作权法（高频考点）

### 3.1 软件著作权的归属

| 情形 | 著作权归属 |
|------|------|
| **职务作品**（利用单位资源、在职期间完成） | 归**单位**所有 |
| **委托作品**（甲方委托乙方开发） | 合同有约定按约定；无约定归**受托方（乙方）** |
| **个人作品**（利用个人时间和资源） | 归**个人**所有 |

> 高频考点：委托开发软件，合同没有约定著作权归属，则归**受托方（开发方）**所有！

### 3.2 保护期限

- **法人/单位**的软件著作权：**50年**（从发表之日起）
- **个人**的软件著作权：**作者终身 + 50年**

### 3.3 合理使用

以下情形不构成侵权：
- 为个人学习研究目的使用
- 为课堂教学目的少量复制
- 为国家机关执行公务使用

## 四、政府采购法（高频考点）

### 4.1 政府采购方式

| 方式 | 说明 | 适用场景 |
|------|------|------|
| **公开招标** | 最主要的采购方式 | 达到公开招标数额标准 |
| **邀请招标** | 邀请3家以上供应商 | 技术复杂或特殊，供应商有限 |
| **竞争性谈判** | 与3家以上供应商谈判 | 技术复杂、无法确定详细规格 |
| **单一来源采购** | 只与1家供应商采购 | 只有唯一供应商、紧急情况 |
| **询价** | 向3家以上供应商询价 | 规格标准统一、现货供应 |
| **竞争性磋商** | 与3家以上供应商磋商 | 政府购买服务等 |

> 记忆：政府采购有**6种方式**，公开招标是主要方式，单一来源是例外

### 4.2 政府采购的原则

公开透明、公平竞争、公正、诚实信用。

## 五、重要标准规范（高频考点）

### 5.1 软件生存周期标准

| 标准编号 | 名称 | 核心内容 |
|------|------|------|
| **GB/T 8566-2007** | 信息技术软件生存周期过程 | 软件开发全生命周期的过程框架 |
| **GB/T 8567-2006** | 计算机软件文档编制规范 | 软件文档的种类、格式和内容要求 |
| **GB/T 9385-2008** | 计算机软件需求规格说明规范 | 需求规格说明书的编写规范 |
| **GB/T 9386-2008** | 计算机软件测试文件编制规范 | 测试文档的编写规范 |

### 5.2 质量与测试标准

| 标准编号 | 名称 |
|------|------|
| **GB/T 18905** | 软件工程产品评价（共6部分） |
| **GB/T 16260** | 软件工程产品质量（共4部分） |

### 5.3 软件工程基础标准

| 标准编号 | 名称 |
|------|------|
| **GB/T 11457-2006** | 信息技术软件工程术语 |
| **GB/Z 31102-2014** | 软件工程知识体系指南（SWEBOK） |

> 考试中通常只考标准的**用途和适用场景**，不考具体条款内容

## 六、高频考点汇总

1. **合同成立**：要约 + 完全承诺（有修改 = 反要约）
2. **招标方式**：公开招标（主要）vs 邀请招标（特殊情况）
3. **评标委员会**：5人以上单数，专家不少于2/3
4. **软件著作权**：职务作品归单位；委托作品无约定归**受托方**
5. **政府采购6种方式**：公开招标、邀请招标、竞争性谈判、单一来源、询价、竞争性磋商
6. **GB/T 8566**：软件生存周期过程标准（最常考）
7. **GB/T 8567**：软件文档编制规范

## 七、易错点

- ❌ 委托开发软件，著作权归委托方（甲方） → ✅ 无约定时归**受托方（乙方/开发方）**
- ❌ 邀请招标只需邀请2家 → ✅ 邀请招标需邀请**3家以上**
- ❌ 评标委员会可以是偶数人 → ✅ 必须是**5人以上单数**
- ❌ 政府采购只有公开招标和邀请招标 → ✅ 共有**6种方式**
- ❌ 承诺可以附加条件 → ✅ 附加条件的承诺是**反要约**，合同未成立
